# 当前版本与 H5 / 手机适配范围

记录日期：2026-10-31。

## 当前 SWF 兼容运行方案

本版本已经是通过浏览器网页承载的方案：Ruffle 的 JavaScript/WebAssembly 运行库执行原 AVM1 SWF。没有把 ActionScript 转译为 JavaScript，也没有重新实现战斗或关卡。

集成版主文件为 SWF 8、400×300、25 fps，另加载三个角色 SWF。四个游戏文件原始字节未修改；本仓库将依赖放在原相对路径下，避免主文件能启动但角色加载失败。Ruffle 及全部游戏文件都在本地提供。

## 两种“H5改造”

1. 在当前 Ruffle 容器上加移动端界面：虚拟摇杆、多点触控攻击/跳跃、松键清理、横屏布局和真机兼容测试。无需重写原游戏规则，通常是较小的适配项目；精确工期取决于输入接口验证和目标手机实测结果。
2. 转成独立 TypeScript/JavaScript 游戏：复用恢复出的图片、声音与规则，重建时间轴事件、碰撞、连招、敌人、关卡和存档。此前静态分析导出了3816个脚本块（不是3816个独立类），说明不能按普通网页容器改造估算；属于明显更大的重构项目。

## 手机上需要验证的事项

- 手机浏览器可运行 Ruffle 并不等于本游戏已完成手机适配；当前只有电脑证据。
- 原游戏依赖键盘，现版本已接入 NippleJS 1.0.4 固定摇杆及攻击/跳跃/暂停按钮，通过播放器元素的 KeyboardEvent 桥接默认 WASD/J/K/I；已在桌面浏览器844×390视口看到摇杆驱动第一关角色移动。仍需真实手机验证完整可玩性。
- 必须区分新按下、按住和松开，并验证方向与攻击同时按、多点触控、手指滑出按钮、后台切换与搓招。
- 检查 Android Chrome 和 iOS Safari 的实际帧率、WASM内存、加载耗时、音频启动、全屏和站点存储行为；不承诺所有机型表现一致。
- 本地服务默认只对本机可见，手机不能用自己的127.0.0.1访问电脑服务。现在支持通过 `HOST=0.0.0.0` 显式开启局域网监听，PowerShell 用法见根目录 README；手机网络与实际运行仍需真机验证。
- 单次加载主文件约26.85MB、一个角色约1.96–3.14MB，另有运行库请求；这些是文件体积，不是压缩传输后的准确流量。

## 后续顺序

先验证最小触控输入，再用一台Android和一台iPhone测第一关、暂停/恢复、声音和存档，之后再判断是否需要对特定兼容问题修改运行库或游戏。没有实测前，不给整个独立H5重写承诺固定工期。
