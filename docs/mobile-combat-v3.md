# 移动端与战斗优化 v3

## 摇杆调研

2026-10-31 在内置浏览器查阅 [NippleJS 官方文档](https://github.com/yoannmoinet/nipplejs#optionsmode)。现有项目已内置 NippleJS 1.0.4，无需增加新依赖。

- static：固定中心，触摸偏离中心时立即产生方向；旧版使用此模式。
- dynamic：每次首次触点成为新中心，松手销毁；更符合本次需求。
- semi：在旧中心附近重用摇杆，超出 catchDistance 才重新定位；不保证每次从首次触点起步。
- follow：超过半径时底座跟随手指，减少长拖后反向需经过很大距离的问题。

本次采用 dynamic + follow，8 方向键映射不变；死区从半径的 22% 调为 16%（110px 摇杆约 9px），保留防止手抖误移动的范围。左侧下部为激活区，离屏幕边缘至少 28px；指针捕获继续追踪拖出区域的手指，第二个触点不能抢占摇杆，攻击手指独立持有按键。失焦、切后台、改变尺寸时销毁当前摇杆并释放全部键。

Android 15 模拟器触摸实测：分别从物理坐标 (300,800)、(600,800) 起拖，生成底座的 CSS 局部横坐标为 86.2857、200.571，均匹配对应首次触点；右拖输出 D、左拖输出 A，松手后恢复“已松开”且摇杆 DOM 消失。真机触感仍需要实际设备反馈。

## 布局

手机横屏用全高 4:3 游戏画面，左右控件以半透明浮层覆盖；取消旧版 160px + 228px 固定控件列和下部工具栏预留。设置项折叠到“设置”，暂停保留。超宽屏仍会有保证原画面比例所需的两侧黑边，不拉伸或裁切画面。竖屏仍采用画面上、控件下的布局。

战斗优化模式在菜单/选人时隐藏控件，角色脚本发出 ready 后显示，避免浮层遮住菜单。响应式检查：900×400 中游戏区域为 533×400；1024×768 为 1024×768；390×844 竖屏无水平溢出。

## 游戏脚本

- 在主 SWF 中关闭 18 处敌人接触 `man.zhua` 时自动进入“抓人/被抓”、将敌人命名为 Throw 的事件；敌人伤害和被击逻辑保持原样。
- 龙出和乱舞分别在三位角色的第 355、342 帧实际扣 MP 时恢复最大 HP 的 15%（向下取整，至少 1 点，上限 maxhp）。不复活、不在暂停时回血；没有命中也生效。按钮和方向组合共用这两个帧动作，避免只在按钮路径回血或多段命中重复回血。
- MP 价格仍为 100 / 130，普通攻击和小技能命中回 MP 的改动保留。
- 只改“战斗优化”配置，原版与旧版配置保留。

验证：补丁构建后再次反编译核对 18 个抓取事件已移除、220 个命中回 MP 分支仍存在；字节级测试检查六个回血帧插入位置、原动作保留、回血上限和死亡/暂停边界。Android 0.3.0 重新打包为离线 APK。
