## 方向识别

方向组合主要由不可见的辅助MovieClip时间轴判断，不是角色可见攻击动画。逐角色核对后，仅扩展下列识别器：

| 角色 | Sprite ID |
|---|---|
| 1 | 74,121,154,233,261,458 |
| 2 | 67,112,164,288,310,478 |
| 3 | 67,109,157,261,280,443 |

它们原有帧数依次为176、84、34、24、24、34。将每帧识别动作额外执行一帧，并把本地ActionGotoFrame的零起始目标n映射为2n；帧标签随原帧移动，不改变名称。放置、移除、形状等标签不重复。角色根时间轴与攻击动画时间轴不变。

此方法让每个输入阶段可等待的时间约加倍：原本6帧的窗口约240ms，扩展后约440–480ms。终止帧的无条件回跳可能在第一份动作就执行，所以不能对所有阶段承诺精确2倍。动作先后顺序、中立方向和新按下要求仍保留；没有实现自动放招、方向序列代按或斜方向容错。

来源：既有 `archive/lingdong-hiphop/analysis-integrated/characters-deobfuscated/{1,2,3}/scripts/DefineSprite_*/`。例如角色1 Sprite74 第1–6帧检测下方向，按朝向转入第50或80帧；第80–86帧检测前方向与攻击，进入鬼步1或攻击延迟阶段。其他辅助识别器负责动作过程中的技能衔接。未在角色导出AS中找到外部数值帧跳转指向这些识别器；`mc.onEnterFrameFunc()` 属于残影渲染，不是方向识别器。
