## 玩法结构与可恢复规则

### 角色和动画

1 号角色根时间轴有 545 帧、28 个帧标签，包含站、走、跑、跳、攻击1/2/3、特殊技、冲击、飞空、鬼步、乱舞、抓人、挨打、倒和死亡等状态。2 号角色也有 545 帧，3 号有 546 帧；三者根时间轴均有 28 个标签。

例如 1 号角色：攻击1从第14帧开始，攻击2从第28帧开始，攻击3从第91帧开始。标签只是入口，不代表全招式实际持续时间；`stop()`、`gotoAndPlay()` 和输入分支会改变播放路径。

`characters-deobfuscated/1/scripts/frame_1/DoAction.as` 可读出基础速度5、跳跃初速-15、逐帧重力参数2，主循环调用 `mc.onEnterFrameFunc()`，再根据暂停、空中状态和Y坐标处理深度。前两个角色初始尺寸为87.2×90.1，第三个为120×115.1；不能因为共享标签和基础参数就假定只是换皮。

### 数值、输入与武器

`export/scripts/frame_3/DoAction.as:231-239` 初始化 HP/MP 各100、生命3、等级1、计时99；这些是代码初值，其他流程可能再调整。

`export/scripts/frame_3/PlaceObject2_1816_448/CLIPACTIONRECORD onClipEvent(enterFrame).as` 每帧按 `sowrd` 选择武器属性，再计算技能伤害。六个可见分支为十字剑、十字阔剑、碧血剑、幽魂剑、嗜血魔剑、烈焰阔剑，攻击加成为5/15/10/16/35/25；十字阔剑将角色速度设为3，其余分支设为5。该代码还采样按键形成 `atkpress`、`jumppress`、方向键状态。

这意味着触屏移植必须保留按键边沿、按住和同时按键的差别；简单把一次点击映射为一次攻击，不能完整复原操作。

1号角色 `characters-deobfuscated/1/scripts/frame_1/PlaceObject2_72_10/CLIPACTIONRECORD onClipEvent(enterFrame).as:60-88` 用攻击键和方向键的新按下组合切入“特殊技”，用攻击与跳跃的新按下组合切入“保护”，并在普通攻击分支选择“攻击1/2/3”。`atkpress` 等状态与事件执行顺序都可能影响这些分支，重建时需要保留并测试。

普通敌人的 `export/scripts/DefineSprite_113_e_01/frame_2/PlaceObject2_23_8/CLIPACTIONRECORD onClipEvent(enterFrame).as:2-33` 分别检测玩家 `h1/h2/h3` 判定对象，并扣除 `_root.m_1/m_2/m_3`；这直接证明伤害不是单纯由可见图片决定。敌人自己的攻击在 `DefineSprite_113_e_01/frame_14/DoAction.as:1` 还检查玩家 `shiti`、是否在空中和无敌状态。

### 敌人、关卡和隐藏内容

ExportAssets 中发现 `e_01` 至 `e_11` 的普通敌人符号和 `e_01boss` 至 `e_06boss` 的 Boss 符号。它们是链接符号统计，不直接等于关卡数量或最终敌人种类。

示例普通敌人 `DefineSprite_113_e_01/frame_1/DoAction.as` 初始化HP100、速度3；普通/困难分支攻击值为5/10，并包含 Hit、phit、retort 等参数。该敌人的46帧时间轴用站、走、攻击、挨打、倒、被抓标签组织行为。

关卡容器 `DefineSprite_2459` 有130帧，帧2/19/42/64/92/105分别是 `1STAGE`、`2STAGE`、`2STAGE_1`、`3STAGE`、`3STAGE_1`、`4STAGE`。从代码可恢复隐藏条件：第17帧在 `Time >= 55 && ming1 == false` 时设置 `conceal_1=1`；第35帧在 `hp >= maxhp` 时设置 `conceal_2=1`。这比根据攻略重新猜测条件更可靠，但仍需对照原版运行验证。

### 存档

存档通过 `SharedObject.getLocal("keyset")` 实现，保存按键、外观设置、光标与武器解锁等字段。例：拾取幽魂剑的 `DefineSprite_678_item_yhj/frame_1/DoAction.as:20-21` 将 `sword_3=1` 写入本地对象。安卓端应显式定义存档结构并迁移为本地文件或偏好存储，不能假定这是一份保存全部关卡进度的完整存档。

## 移植建议

1. 以 Godot 作为重建候选，先维持400×300逻辑坐标和25 Hz玩法步进，再独立提高渲染帧率；这是减少手感漂移的工程建议，不是已经验证的实现。
2. 保留原图、声音和矢量资料，生成动画帧与轴心/变换/帧标签数据。不要只导出图片而丢掉时间轴与判定对象关系。
3. 将 `_root` 全局状态、MovieClip 帧脚本和 `hitTest` 逻辑整理成显式玩家/敌人状态机、攻击框、受击框、跳跃与地面坐标、关卡事件。
4. 先实现1号角色与 `e_01` 的移动、普通攻击、跳跃、受击和死亡。对照25fps原版的输入时序、招式有效帧、伤害和击退后，再扩展三角色、装备、隐藏关卡与存档。
5. 排行榜和旧网页按钮应作为独立范围处理。当前没有理由让离线安卓单机流程依赖旧 ASP 网站。
